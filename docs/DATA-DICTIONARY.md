# 数据定义

刷卡事件以event_id去重，card保留前导零。route支持1路/01等别名。event_time必须带偏移；业务日为Asia/Shanghai。result仅success可作为行程，失败刷卡隔离。reported为实扣人民币元。票价F1至2026-11-01前为2元，F2为2.50元。

跨线路换乘必须在上一次实际付费行程后60分钟内，恰好60分钟排除。同线路无优惠；零付费行程不能延长换乘锚点。先扣1元换乘优惠，再对卡号业务日施加6元封顶。每条基本票价=实算扣费+换乘优惠+封顶优惠。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数；`source_span`给出该记录覆盖的物理行首尾，正常文件的区间从第2行起首尾相接、无空缺。

## 公式样式文本

卡号、线路名、备注与隔离说明为上传原文，一律在采信时保留原值，不因此拒收整行：拒收会让来源行失去业务结论并打乱行数，统一改写又会丢掉原值。

- 以 `=`、`+`、`-`、`@` 开头（含前导空格后接上述字符）的单元格记为 `FORMULA_PREFIX`；以制表符或回车开头的记为 `CONTROL_PREFIX`。
- 发布（证据导出）时按 `rendered` 呈现：原值前加单引号，使表格软件按文本处理，文件可安全打开。
- 原值逐字节保存在 `original_b64`（`base64:` 前缀），与呈现值同行可追回；两者都只在发布产物中出现，采信记录不改写。
- 页面“来源行台账”沿来源行展示原值、呈现值与处置原因。

裁决：不因公式样式文本拒收整行，也不在采信时改写原值。拒收会让该来源行失去业务结论、打乱来源行数；改写会丢失原值。因此采信保留原值，由发布环节做安全呈现并同时留存原文，二者在导出中同处一行。

## 来源行台账与封存

M1 为每个物理来源行建立处置：采纳、隔离、重复行、空白行、分段表头；无结论的行记 `unplaced`。M6 对账复核台账（同一行只能有一个结论，缺失区间补为 `unplaced`），M7 在 `unplaced>0` 或台账缺失时以 `LINEAGE_GAP` 拒绝封存。证据导出同样要求台账完整：每个来源行恰好一行，重跑不新增记录，发布失败保留上一版。
